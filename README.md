# 4조 · 단계 1 데이터 점검 (10/16)

## 데이터 한눈에
- 7,535샷 = train 5,274 / public 1,130 / private 1,131
- 라벨 7종: 정상 + 불량 6종 (Short_Shot, Blow_Hole, Exfoliation, Deformation, Stain, 기타불량)
- 평가 지표: Macro F1 (7개 클래스 점수를 똑같은 비중으로 평균)

## 데이터 분석으로 알게 된 것

**1. 제품이 2종이고, 서로 완전히 다르다 → 제품별로 나눠서 봐야 한다**
- shot 1~4207은 Type1, 4208~7535는 Type2 (전환 1번)
- 공정 조건이 다름: 주조압 1052 vs 596, 사이클 21초 vs 36초
- 나오는 불량이 다름: Blow_Hole은 Type2만, Exfoliation·Deformation은 Type1만

| 라벨 | Type1 | Type2 |
|---|---|---|
| 정상 | 82.3% | 71.6% |
| Short_Shot | 5.5% | 13.3% |
| Blow_Hole | 0% | 10.0% |
| Exfoliation | 6.7% | 0% |
| Deformation | 3.6% | 0% |
| Stain | 0.1% | 4.2% |
| 기타불량 | 1.8% | 0.9% |

**2. 정상이 77.6%로 불균형이 심하다 → 정확도가 아니라 Macro F1로 봐야 한다**
- 전부 정상으로 찍어도 정확도는 0.77이지만 Macro F1은 0.12
- 개수가 적은 기타불량(1.4%)·Deformation(2.0%)이 점수를 가장 많이 깎는다

**3. 같은 샷이 두 줄로 기록된 행이 많다 → 무작위 분할 점수는 부풀려진다**
- 바로 앞 행과 Shot 번호·모든 값·라벨까지 같은 행이 2,918개 (shot 1100~4207, 4808~7535)
- 검증 샷과 똑같은 행이 학습에 들어가서, 모델이 외워서 맞히는 효과가 생긴다

**4. 라벨은 여러 불량 중 하나만 남긴 것이다 → 일부 불량 정보가 사라졌다**
- 불량이 두 종류 이상 함께 나오면 우선순위가 높은 것만 라벨로 남김 (Short_Shot이 가장 우선)
- 그래서 Stain은 원본에 146번 기록됐지만 라벨에는 100개만 남았다

## 확정 전처리 (무조건 적용)

| 전처리 | 내용 | 이유 |
|---|---|---|
| 식별열 제외 | shot_id, id, Shot을 피처에서 뺌 | 규칙상 사용 금지 |
| 상수 열 제거 | 고유값 1개이면서 결측 없는 4개 (Air_Pressure_Min/Max, Coolant_Temp_Min/Max) | 값이 하나뿐이라 정보 없음 |
| 0값 대치 | High_Velocity·Rapid_Rise_Time·Pressure_Rise_Time의 0 → 정상 라벨 행의 중앙값 | 고속 사출 없이 쏜 비정상 가동 샷 (3348·3349·3420·3421) |
| 결측 대치 | Factory_Temp·Humidity 등 결측 63행 → 제품별(Type1·2) 중앙값 | 제품마다 값 범위가 다름 |

## 실험 결과 (랜덤포레스트, 팀원 코드 조건)

| 실험 | Macro F1 |
|---|---|
| 전처리 없음 | 0.4560 |
| 확정 전처리 적용 | 0.4597 |
| 중복 제거 | 0.3556 |

- **전처리를 해도 점수는 거의 그대로다.** 랜덤포레스트는 이상치·상수 열에 둔감하다.
- **중복을 제거하면 성능이 낮아진다 (−0.10).** 외워서 맞히던 효과가 사라진 것이다.
- **리더보드 점수도 높게 나올 수 있다.** private 1,131샷 중 607샷이 train에 똑같은 행이 있다.
