# 결과 페이지 발표 대본 · 3조

<b>합계 약 9분 5초.</b> 결과 페이지(대시보드 → 결과 리포트)를 화면에 띄워 놓고 팀장이 설명할 때 쓰는 대본입니다.

읽는 법: <b>화면</b>은 손으로 할 일, <b>말할 것</b>은 그대로 읽어도 되는 문장, <b>짚을 곳</b>은 포인터로 가리킬 곳입니다. 말할 것 안의 굵은 대괄호는 말하지 않고 하는 동작입니다. 숫자는 결과 페이지 화면 글자, 3조 최종 보고서(10/28판)와 같습니다.

## 열기 준비

결과 페이지 폴더(받은 폴더 이름은 `3조_결과페이지`, 레포에 옮겼다면 옮긴 폴더)의 `index.html`을 크롬으로 엽니다(더블클릭). 폴더 안 파일은 떼지 말고 폴더째 둡니다. 인터넷이 없어도 열립니다(글꼴만 기본 글꼴로 바뀝니다). 열리면 F11로 전체 화면으로 바꿉니다(맥은 Ctrl+Cmd+F).

- 첫 화면이 <b>대시보드</b>이고, 열자마자 1× 속도로 생산을 시작합니다. 왼쪽 메뉴 맨 아래 <b>「결과 리포트」</b>가 결과 스토리 페이지입니다.
- 결과 리포트 안에서는 위쪽 칩(데이터 · 학습 · 결과 · 제출 선택 · 시행착오 · 제안)을 누르면 그 장으로 갑니다. 장 안에서는 마우스 휠로 내립니다. 지금 보는 장의 칩이 진한 초록으로 바뀝니다.
- 대시보드 오른쪽 위 「리포트 보기」는 인쇄용 생산 리포트로 가는 버튼입니다. 발표 중에는 누르지 않습니다.

## 발표 직전 체크

- 발표장 PC와 프로젝터에서 미리 열어 결과 리포트 끝까지 내려 봅니다. 기준은 1920×1080 전체 화면입니다. 글자가 잘리면 Ctrl + - 로 줄입니다.
- 대시보드는 지난번에 멈춘 다음 샷부터 이어서 돕니다. 발표 직전에 왼쪽 메뉴 「입력 기록」에서 「처음부터 다시」를 두 번 누릅니다(첫 번째에 「한 번 더 누르면 기록 삭제」로 바뀝니다). 대시보드로 돌아가 SHOT #381부터 다시 돌면 바로 「일시정지」를 눌러 두고, 장면 0에서 「계속」을 누릅니다.
- 속도는 1×에 둡니다. 3×·8×는 누르지 않습니다.
- 결과 리포트의 퀴즈와 버튼은 새로고침(F5)하면 처음 상태로 돌아갑니다. 리허설 뒤에 한 번 F5를 누릅니다. 데이터 장의 슬라이더는 10%에 그대로 둡니다(움직이면 「차이」 숫자가 바뀝니다). ④ 운영 기준은 「시간순 (배포 판단)」 · 「배율 1.0」 · 「10건」 · 검사 가능 수량 빈칸이 기본입니다.
- 「제출 선택」 표에 주황 「팀이 확인할 것」 칸(1·6회차 모델 등)이 있습니다. 발표에서는 읽지 않고, 물으면 팀이 실제로 한 대로 답합니다.
- 루브릭 그림 5종은 결과 리포트 「결과」 장에 차례로 있습니다. ① 학습곡선 = 장면 5, ② 혼동행렬 = 장면 6, ③ 특징중요도 = 장면 7, ④ 운영 기준 = 장면 8, ⑤ 불량 원인 = 장면 9입니다. ④는 대시보드 「경보 기준」 카드, ⑤는 대시보드 주의 조건 줄에도 나옵니다.
- ③ 특징 중요도는 최종 KNN이 아니라 공정 변수를 더한 랜덤포레스트의 중요도입니다. 말할 때 이 말을 빼지 않습니다.

## 0. 현장에 붙이면 이렇게 돕니다 — 50초

<b>화면</b>

- 대시보드가 일시정지된 상태(SHOT #381 · 제품 1)에서 시작합니다. 셋째 문장 뒤 <b>[「계속」 누르기]</b> 자리에서 「계속」을 누릅니다.
- 공정 그림 위 단계 칩(① 주탕 → ② 사출 → ③ 냉각 → ④ 형개 · 취출 → ⑤ AI 판정 · 기록)이 차례로 켜지고, 계기판 점은 그 샷의 실제 값으로 움직입니다.
- 처음부터 다시 돌렸다면 두 번째 샷 #386이 「미충전 → 검사」 경보입니다. 주물이 게이트 뒤 갈림판에서 위쪽 「검사 라인」으로 가 검사 통에 떨어집니다. 정상 샷은 컨베이어 끝 양품 통으로 갑니다.
- 그림 바로 아래 배지가 샷마다 「학습에 같은 기록 있음」(초록) / 「없음」(회색)으로 바뀝니다.

<b>말할 것</b>

> 3조입니다. 저희 질문은 「금형을 열기 전에 불량을 알 수 있는가」입니다. 먼저 이 모델을 현장에 붙이면 어떻게 도는지 보여 드리겠습니다. <b>[「계속」 누르기]</b> test 샷을 생산 순서대로 다시 돌린 화면입니다. 공정 기록 21개로 KNN이 판정해, 경보 샷은 위쪽 검사 라인으로, 정상은 양품 통으로 보냅니다. 그림 아래 배지는 이 샷과 21개 값이 똑같은 기록이 학습 데이터에 있었는지입니다. 검증에서 같은 기록이 있는 샷은 불량의 92%를 잡았고, 없는 샷은 13%만 잡았습니다. 그래서 「모델 기대 성능」에는 처음 보는 시기 기준 불량 탐지율 19.5%를 걸었습니다.

<b>짚을 곳</b>: 경보 샷이 올라가는 「검사 라인」 → 배지 「학습에 같은 기록 있음/없음」과 옆 문구 「불량 92%를, 없는 샷은 13%」 → 아래 「모델 기대 성능」 카드 「19.5%」

## 1. 제품 전환과 주의 조건 — 50초

<b>화면</b>

- 속도 줄의 「제품 전환 보기」를 누릅니다. 제품 1이 제품 2로 바뀌기 세 샷 앞(#4196)으로 갑니다. 이 세 샷은 배지가 「학습에 같은 기록 있음」입니다.
- 누르고 약 9초 뒤 금형이 열리고 새 금형으로 바뀌며, 안내 카드 「금형 교체 · 제품 1 → 제품 2 / 주조압 1,052 → 595 · 사이클 20.9초 → 36.0초」가 뜹니다.
- 제품 2 첫 샷 #4208부터 냉각수 온도 옆 빨간 점이 깜빡이고, 그림 아래 줄에 「기공 주의 · 냉각수 온도 ≤ 26.4°C → train 기공 23.4% (26.4°C 초과는 6.2%)」가 뜹니다. #4208이 판정되면 배지가 「학습에 같은 기록 없음」으로 바뀌고, 생산 기록에 「→ 정상 · 양품함 ! 기공 조건」이 남습니다.
- 다 말하면 왼쪽 메뉴 맨 아래 「결과 리포트」를 누릅니다.

<b>말할 것</b>

> <b>[「제품 전환 보기」 누르기]</b> 이번에는 제품이 바뀌는 장면입니다. 지금 지나가는 제품 1 샷들은 배지가 「학습에 같은 기록 있음」입니다. <b>[「금형 교체」 카드가 뜨면]</b> 금형을 바꾸면 주조압이 1,052에서 595로, 사이클이 20.9초에서 36.0초로 바뀝니다. <b>[제품 2 첫 샷이 판정되면]</b> 제품 2로 넘어가자 배지가 「없음」으로 바뀌고, 냉각수 온도 옆 빨간 점이 깜빡입니다. 학습 데이터에서 기공이 23.4%였던 냉각수 조건입니다. 모델은 이 샷을 정상으로 보냈습니다. 처음 보는 샷은 판정만 믿기 어려워서 주의 조건을 따로 띄웠고, 이 조건은 원인이 아니라 관련성입니다.

<b>짚을 곳</b>: 안내 카드 「주조압 1,052 → 595」 → 냉각수 온도 옆 빨간 점 → 그림 아래 「기공 주의」 줄 → 생산 기록 「→ 정상 · 양품함 ! 기공 조건」

<b>짚을 곳</b>: 숫자 카드 「0.589」 → 「0.570 → 0.138」 → 「45 / 231」 → 「58.7%」

<b>짚을 곳</b>: 퀴즈 정답 「58.7%」 → 오른쪽 숫자 「3,097」 · 「57.7%」

## 4. 어느 점수가 현장 성능인가 — 40초

<b>화면</b>

- 위쪽 칩 「학습」을 누릅니다. 「베이스라인 비교」 막대에서 시작합니다.
- 계속 내려 「어느 점수가 현장 성능에 가까울까요?」에서 「시간순 80/20」 카드를 누릅니다. 오른쪽 문장이 「맞습니다. 시간순 0.138이 배포 성능에 가깝습니다.」로 바뀝니다.

<b>말할 것</b>

> 로지스틱 · 랜덤포레스트 · 신경망(PLR MLP) · KNN을 같은 5-fold 검증으로 비교하면 KNN이 0.5825로 가장 높고, 랜덤포레스트 0.5714와는 거의 같습니다. <b>[「시간순 80/20」 누르기]</b> 그런데 같은 KNN을 시간순으로 나누면 0.138입니다. 무작위로 섞으면 검증 샷의 48%가 학습에 같은 값 샷을 갖고, 시간순은 0.1%뿐입니다. 현장에서 판정할 샷은 아직 생산되지 않은 샷이라, 배포 성능은 시간순 쪽입니다.

<b>짚을 곳</b>: 초록 막대 「KNN (최종) 0.5825」 → 아래 「시간순 80/20 0.138」 → 오른쪽 「48%」 · 「0.1%」

## 5. ① 학습곡선 — 35초

## 7. ③ 특징중요도 — 25초

<b>화면</b>
